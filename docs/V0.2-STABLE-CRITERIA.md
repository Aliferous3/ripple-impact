# v0.2.0 stable — promotion criteria

Gates that must all hold before Python loses the `experimental` label
and v0.2.0 ships stable. Popularity metrics (stars/downloads) are
explicitly **not** criteria — adoption is not correctness.

## Required

- [ ] **No known P0** — no source-exposure/privacy defect open.
- [ ] **No unresolved systematic Python false-positive class** —
  individual bounded FPs may remain documented; a *class* (e.g. every
  reference of kind X becoming a call) blocks.
- [ ] **Installation verified on Windows + Linux** — Python adapter
  included; the scip-python 0.6.6 Windows shim must not have regressed.
- [ ] **macOS disposition decided** — either verified, or explicitly
  documented as unverified/unsupported in README + docs.
- [ ] **Python runtime/type separation remains sound** — re-audit
  `calls` vs `references` vs `type_depends` on representative repos.
- [ ] **Deletion/base reconstruction reliable** — tombstones + former
  callers correct on the dogfood matrix.
- [ ] **TS/JS parity remains 20/20** vs released v0.1.0.
- [ ] **Representative public Python repos pass** — the dogfood corpus
  in `docs/BETA-DOGFOOD-0.2.md` clean, plus any new blockers fixed.
- [ ] **Package/security gates clean** — `npm audit --omit=dev` = 0,
  no `.pyc`/cache/venv leaks, path/secret scan clean.
- [ ] **External users had a reasonable chance to report failures** —
  the feedback issue has been open long enough for real-world signal;
  silence alone is not proof, but launching stable the same week as
  beta.1 is wrong.

## Explicit non-criteria

- Star/fork/download counts
- Supporting every Python project or every dynamic pattern — the
  documented honest-miss list is the supported boundary
- Cross-language edges — out of scope for v0.2.0
